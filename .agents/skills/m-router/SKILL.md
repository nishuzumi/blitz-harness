# Monad Harness 路由器

你不需要记住每个 Harness 技能。先判断局面，再替用户路由。

**流程** 是穿过多个技能的一条路径。多数工作沿着一个 **主流程**：
**想法 → 提交**。少数 **入口** 会汇入主流程，其余是独立事项。

## 主流程：想法 → 提交

这是大多数黑客松工作的路线。参赛者要把不确定的方向，推进成可提交的
Monad 演示项目。

1. **`m-start`** 初始化状态、文档、进度和截止时间上下文。
2. **分支：用户是否已有想法？**
   - **没有** → **`m-scout`** 生成候选 Monad 想法并打分。
   - **有** → **`m-idea`** 把粗略想法整理成项目卡片。
3. **`m-grill`** 用访谈把想法磨尖。项目太大、太虚、缺用户、缺 Monad
   必要性、缺演示路径时，从这里开始。
4. **分支：演示路径能否在对话里定下来？**
   - **能** → 进入 **`m-build`**。
   - **不能** → 留在 **`m-grill`**，继续砍范围。
5. **`m-build`** 把打磨后的想法变成构建计划和 monskill 交接。
6. **分支：项目是否已经能提交？**
   - **不能** → 继续构建，但每次任务后检查截止时间风险。
   - **能** → **`m-submit`** 准备 README 和提交文案。
7. **`m-pitch`** 生成 3 分钟路演、讲稿、演示顺序和评委问答。

### 上下文卫生

尽量把 1 到 5 步保持在同一个连贯上下文里，让想法、追问和构建计划沿着同一套判断推进。
如果会话过长或用户重启，把状态写进 `docs/status.md`，再从本地文件继续，不要让用户重讲。

文件和记忆冲突时，不要相信记忆。读取：

- `.mon-harness/state.json`
- `.mon-harness/progress.json`
- `docs/status.md`
- `docs/idea.md`
- `docs/build-plan.md`

未初始化必须先执行 **`m-start`**。如果 `state.stage` 是 `empty`、
`docs/status.md` 显示未初始化、或 `next_command` 是 `$m-start`，先读取
`.agents/skills/m-start/SKILL.md` 并执行它，再回答用户。

用户问“你能帮我做什么”“现在做什么”“帮我开始”“测试一下”时，若仓库未初始化，
都算启动意图。不要先进入 `m-status`，不要只解释能力。

## 入口

入口是一种起始局面，会先产生工作，再汇入主流程。

- **空白开局** → **`m-scout`**。用户选定想法后，汇入 **`m-grill`**。
- **用户贴了粗略想法** → **`m-idea`**。结构化后，汇入 **`m-grill`**。
- **范围失控** → **`m-grill`**。砍到能演示为止。
- **截止时间恐慌** → **`m-status`**。先找最大缺口，再路由到 **`m-build`**、
  **`m-submit`** 或 **`m-pitch`**。
- **没有计划就开始写代码** → 先用 **`m-build`**。不要让代码工作越过演示路径。
- **README 或提交材料混乱** → **`m-submit`**。
- **路演材料混乱** → **`m-pitch`**。

## 构建健康

这不是单独命令，而是流程里的维护动作。

- 代码变化后，检查 README、提交材料、路演和演示路径是否仍然准确。
- 临近截止时间时，如果演示、提交或路演还是 `todo`，先回答当前问题，再提醒风险。
- 用户说某项已完成、跳过或提交后，更新 `.mon-harness/progress.json`。

## 跨会话

- **本地文件** 就是交接。会话重启后，先读状态和文档，不要让用户复述。
- **`docs/status.md`** 是压缩后的工作摘要。
- **`docs/idea.md`**、**`docs/build-plan.md`**、**`docs/submission.md`** 和
  **`docs/pitch.md`** 负责跨上下文保存项目状态。
- 用户最新消息和本地文件冲突时，相信用户并更新文件。

## 独立事项

这些不属于主流程，但仍由本技能路由。

- **状态检查** → 用户问“现在做什么”“进展到哪”“哪里有风险”，或中断后回来时，用
  **`m-status`**。
- **赛事信息更新** → 更新 `docs/event.md`，再运行 **`m-status`**。
- **进度更新** → 更新 `.mon-harness/progress.json`，再运行 **`m-status`**。
- **模板检查** → 验证模板时运行 `bash scripts/doctor.sh`。

## 前置条件

仓库必须包含：

- `AGENTS.md`
- `.agents/skills/m-router/SKILL.md`
- `.mon-harness/state.json`
- `.mon-harness/progress.json`
- `docs/status.md`

如果缺少任何文件，先修复 Harness，再路由。永远不要让用户自己选择技能。

路由时，先解决用户当前请求。然后简短说明进入了哪个阶段，提醒一个截止时间或材料风险，
并只给一个下一步动作。
